# Context-First English Learning — 划词浮窗 UI/UX 设计规范

**版本**：v0.7（设计讨论汇总）  
**整理日期**：2026-10-22  
**状态**：设计基线，待交互原型验证  
**范围**：网页/视频划词后浮窗的 UI/UX；不包括客户端实现架构、后端、模型选型、词库完整页面。

## 1. 产品体验目标

用户在阅读文章或观看视频时，选中陌生表达，即可在原位置附近看到该词在当前语境中的含义、原句翻译和简洁的 Context 解释；可以局部展开、追问 AI 或收藏，而无需切换页面。

**核心原则**：安静的界面、清晰的信息层级、最少的操作。AI 在背后完成理解，不把浮窗做成大型聊天界面。

## 2. 用户主动提出的设计方向（Initiatives）

这些是讨论中由产品发起人主动提出、应在后续设计中保留的意图：

1. **奥卡姆剃刀**：谨慎判断哪些决定交给用户，避免功能与 AI 输出堆积。
2. **翻译不仅是词义**：希望提供整句翻译、上下文及「为什么这里可以这么用」。
3. **轻量 AI 辩论入口**：保留一个窄的对话入口，点击后可扩展讨论，但不作为主要视觉冲击。
4. **自适应、非全屏浮窗**：无传统窗框，适应内容；翻译及 Context 有默认展示上限，可单独展开。
5. **毛玻璃与阴影**：浮窗应柔和、轻盈，而非厚重的多层卡片。
6. **简笔画彩蛋**：一只淡淡的线稿鹅，从浮窗右侧向左探头，藏在卡片背后。
7. **小鹅具体调整**：线条更淡、无头顶装饰线、鹅头向左移动并与右侧边缘部分重叠。
8. **简洁状态反馈**：反对「原句已经保留」「不会重复收藏」等防御性工程文案；行业中已足够明确的图标不重复解释。
9. **轻快动效**：不追求炫技，先选择常见桌面工具的快速动效参数，再实际测试。
10. **来源可追溯**：希望取得 URL、播放进度及元信息，并有简短的「在哪里看到的」说明；这一点当前只影响浮窗底部的来源展示，数据架构另议。

## 3. 视觉设计（基本确定）

### 3.1 风格

- **名称**：Warm Paper / Soft Glass / Borderless Floating Panel。
- 暖白、接近不透明的半透明背景；整体微弱毛玻璃感。
- 单层内容容器，避免灰色托盘、卡片套卡片、大面积色块与重边框。
- 圆角、柔和低对比阴影；必要时可加入几乎不可见的 1px 描边，适配白色网页背景。
- 不使用常驻渐变光效、霓虹、AI Sparkles 或持续运动装饰。
- 强调色为低饱和鼠尾草绿，用于当前词重点、展开与操作反馈。

### 3.2 初始 Design Tokens（均为候选值，须校准）

| Token | 初始值 | 备注 |
|---|---|---|
| `surface` | `rgba(250,250,248,.92)` | 暖白玻璃背景 |
| `text.primary` | `#28312B` | 主文字 |
| `text.secondary` | `#5B655D` | 译文/辅助文字 |
| `text.muted` | `#909A92` | 来源/弱提示 |
| `accent` | `#52755D` | 鼠尾草绿 |
| `radius.panel` | `16px` | 无传统标题栏 |
| `blur.panel` | `20px` | 仅在支持且可读时启用 |
| `shadow.panel` | `0 3px 10px rgba(0,0,0,.04), 0 16px 48px rgba(0,0,0,.10)` | 柔和双层阴影 |
| `border.panel` | 无或 `1px solid #E9EAE5` | 待真实背景 AB 对比 |
| `text.body` | 约 `14px` | 允许系统字体缩放 |
| `panel.width` | 约 `420px` | 待设备/DPI 验证，不是强制固定 |

### 3.3 小鹅彩蛋

- **选定版本 B**：位于浮窗右边缘外侧，**从卡片背后向左探头**。
- 只露出头与少量脖子；部分轮廓与右侧卡片边界发生遮挡，脖子被卡片盖住，形成真实的前后层次。
- 单色、细线、极低不透明度；无头顶装饰线、无大幅表情、无填充色。
- 不覆盖正文、不可拦截点击/文本选择；默认静态，是否在收藏时短暂动作属于可选实验。
- 小鹅是装饰，不承担加载、成功、错误提示。
- 实现需考虑透明窗口安全边距和裁剪；最终姿态以可编辑矢量稿校准，而非生成图片的像素尺寸。

## 4. 信息架构与展示优先级

默认由上至下：

1. **目标表达**（最强视觉权重）、上下文词义；右上角收藏与关闭图标。
2. **英文原句**：保留原文，选中表达可做轻微强调。
3. **中文整句翻译**：自然文本，不必单设灰色卡片。
4. **Context**：合并「语境是什么」和「为什么这样使用」；用短解释优先展示最有用的信息。
5. **继续讨论…**：底部轻量入口，需要时展开输入与对话记录。
6. **来源**：底部小号弱化信息，如站点名、视频时间（如可得），点击返回来源。

默认内容应简洁。长文本按**行数/实际溢出**截断，末尾内联「展开」，独立展开/收起；不应每个区块始终出现展开按钮。建议初始尝试：句子译文最多约 2–3 行；Context 最多约 2–3 行。具体阈值以真实排版测试为准。完整原文和详细解释不因截断被删除。

**信息真实性**：Context 仅能根据实际获得的原文与邻近上下文解释；不足以判断时不假装已读完整文章。不要强行生成词源故事或无依据的语义分析。

## 5. 行为与交互

### 5.1 划词触发

- 用户主动选中词或短语并触发查词；浮窗出现于阅读环境内，不强制切换应用。
- 优先一次只显示一个浮窗。连续查词复用同一容器，切换对应内容与会话上下文，避免窗口叠加。
- 浮窗初始不应强制自动暂停视频；是否暂停可后续验证。
- 选中内容及原句优先可见，AI 解释异步填充；不以模型成功为显示前提。

### 5.2 局部展开

- 句子翻译和 Context 分别展开、收起；仅当实际溢出时出现入口。
- 展开主要改变高度，不突然扩大宽度或全屏化。
- 窗口高度有限，超过可用区域则内部滚动；避免遮挡屏幕边界。

### 5.3 AI 讨论

- 默认仅保留弱化的「继续讨论…」入口，可配通用消息图标。
- 点击后展示输入区，支持围绕当前词、原句及上下文多轮追问与质疑。
- 不因为输入框获得焦点就突然大幅横向扩张；深入讨论是否加宽可在原型中测试。
- 切回此前表达时，其讨论属于该次捕获，不与其他表达混合。
- 关闭讨论区不应立即清空当次未发送输入（同一捕获会话内）。

### 5.4 图标与文案

- 公认含义明确的图标单独使用：关闭 `×`、收藏书签、展开/收起箭头、播放发音等。Hover/Focus 时提供必要可访问名称。
- 「继续讨论」这种语义不够唯一的操作保留简短文字。
- 不使用无明确含义的 AI 魔法图标作为核心导航。
- **不要暴露实现关切为 UI 文案**：例如删除「不会重复收藏」「原句已经保留」之类的说明。后台防错照常实现。

## 6. UI 状态

采用独立状态维度，而非为每种组合单独设计页面：

| 维度 | 状态 | 可见反馈 |
|---|---|---|
| 面板 | Hidden / Visible | 出现与消失 |
| 解释 | Loading / Ready / Error | 占位、内容、轻量「重试」 |
| Context | Collapsed / Expanded | 溢出才显示展开 |
| 讨论 | Closed / Composing / Conversation | 小入口、输入框、消息记录 |
| 收藏 | Unsaved / Saved | 书签图标填充/还原 |
| 来源 | Available / Partial / Missing | 有则显示，不可用则不编造 |

推荐微文案：`正在解释…`（可不显示，仅用轻量占位）、`重试`、`继续讨论…`。错误提示只说明用户需要知道、可以采取的动作。语义不确定性确实影响结论时，必须准确表达，不能为简洁牺牲真实性。

**边界场景**：前一词的较慢 AI 请求不得覆盖后一词；失败不删除原始文本；关闭浮窗不等于删除收藏；重复选词不叠加新窗；内容增长不应造成明显抖动。

## 7. 动效 Motion v0.1（暂定）

**基准时长：180ms**，仅为初始设计数值，并非经过统计的行业中位数。

| 动作 | 时长 | 初始方向 |
|---|---:|---|
| 浮窗出现 | 160ms | 淡入 + 上移约 4px，ease-out |
| 浮窗关闭 | 120ms | 快速淡出，ease-in |
| Context 局部展开 | 180ms | 高度平滑变化 |
| 讨论区展开 | 200ms | 平滑出现 |
| 单词切换 | 120ms | 轻淡变更，保持位置 |
| 收藏反馈 | 140ms | 图标状态变化 |
| Hover | 100ms | 弱反馈 |

初始曲线可尝试 `cubic-bezier(.2,0,0,1)`。禁止为等动画而延迟可用内容；减少动态效果设置下移除位移/缩放。

## 8. 尚未冻结，需前端原型验证

- 浮窗相对选区、鼠标或屏幕角落的位置；自动避让原文及视频字幕。
- 点击浮窗外侧是否关闭、是否允许固定、拖动以及跨显示器行为。
- 系统级独立桌面透明窗口 vs 浏览器扩展页面内浮层：视觉相似但能力不同，需客户端架构阶段决定。
- 不同 DPI/缩放及窗口尺寸、最大高度、长句与中文换行。
- 毛玻璃实现方式、性能、系统降级和浅色页面边缘辨识度。
- 键盘导航、Esc/Enter、输入焦点、窗口置顶和可访问性。
- 小鹅最终可编辑线稿与准确遮挡关系。
- 来源位置的压缩显示以及视频暂停策略。

## 9. 交付与验收建议

**前端交付**：静态 Mockup 参考图 + 可编辑 UI 实现 + 本规范。图片不是像素级技术参数来源。

至少用模拟数据实现并测试以下场景：

1. 普通短句解释成功；无多余的「展开」。
2. 长译文、长 Context 分别展开/收起，面板稳定。
3. Loading → Ready、Loading → Error → Retry。
4. 收藏切换与底部讨论输入展开。
5. 连续划词、快速切换词、过期请求返回。
6. 1080p、1440p、4K 不同缩放与较小窗口；浅色/复杂背景下文字可读。
7. 小鹅不遮挡内容、不截获指针事件；减少动态效果模式可用。

**验收原则**：不以「设计看起来舒服」替代真实使用验证。先用真实网页进行高频划词测试，再调整尺寸、定位与动效。

---

### 设计结论（一句话）

> 一个暖白毛玻璃、按内容自适应的安静划词浮窗：一眼看懂当前表达，需要时展开 Context 或与 AI 继续辩论；右侧藏着一只极淡的探头鹅。
