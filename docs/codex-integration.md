# Codex 接入与验证

首版通过本机 `codex app-server` 提供解释与追问。实现位于 `src/providers/codex.ts`，与界面和收藏存储之间只使用 `AIProvider` 接口；以后可以增加用户提供的 API 实现。

## 使用条件

- 本机安装 Codex 0.164.0 或更新版本，并先在 Codex 中完成登录。应用启动连接前检查版本，避免旧版忽略隔离会话所需的参数。
- 默认无需填写 Codex 路径或模型。应用查找 PATH、Windows npm 安装目录、Windows Codex 桌面应用的版本目录，以及 VS Code/VS Code Insiders 的 OpenAI 扩展目录；自动跳过无法启动或版本不兼容的候选程序。自动发现的路径不会写入设置，避免升级后固定在旧版本；旧版保存的路径已不存在时也会重新查找。手动覆盖项收在“高级设置（可选）”，可恢复自动连接。
- 模型设置为空时使用当前 Codex 配置的模型。应用在每轮使用 `low` reasoning effort，降低简单解释任务的推理开销，不改写用户的全局配置。
- Windows 和 Linux 使用相同的协议实现，各自使用对应系统的可执行文件和登录状态。

程序调用 `account/read` 确认认证状态，不读取、复制或输出认证文件。认证状态不存在时，界面提示先登录 Codex。可执行文件路径来自明确设置或程序发现，启动过程不经过 shell 拼接。

## 连接与数据流

首次请求启动一个常驻 App Server 并完成 `initialize` / `initialized` 握手。每次捕获建立独立的临时 thread；当前捕获的后续追问使用同一 thread。连接中断后会在下次请求重新连接，不把其他捕获的内容混入当前上下文。

初次解释通过 `turn/start.outputSchema` 取得结构化内容，在完整结束并通过 schema 检查后显示和保存；原文可先显示。追问通过消息 delta 逐步显示，完整结束后才进入收藏的讨论记录。切词或取消会发送 `turn/interrupt`，迟到事件由会话控制层进一步过滤。相关协议见 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)。

请求只包含表达、已捕获的有限原文、可确认的原句，以及当前捕获的讨论内容。模型不生成来源 URI、capture ID 或时间。`provider`、实际使用的 `model` 和 `generatedAt` 由应用追加。

协议请求有 30 秒超时；一次解释或追问默认最多等待 120 秒。超时会尝试取消；取消协议失效时关闭连接，下一次操作可重新建立连接。不存在成功的最终结果时，不保存流式片段为完整解释。

## 文本模式的能力限制

应用以临时启动参数关闭 shell、插件、应用工具、浏览器/电脑操作、多代理、hooks 等能力，并逐个禁用有效配置中的 MCP 服务。随后再次读取有效配置，确认关键限制生效；无法确认时拒绝发起解释。Codex 的配置项依据 [官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)，仍需针对安装版本验证。

thread 和 turn 都显式传入空的 `environments`，不提供动态工具或选定的能力根，并使用只读沙箱。客户端拒绝所有服务端发来的工具、审批或其他操作请求；若事件流仍出现非文本操作，就终止该连接。

启动参数只影响本应用启动的进程。应用不修改用户的 Codex 全局配置或登录；子进程环境仅继承登录位置、PATH、系统/代理变量和当前模型提供方需要的密钥变量。标准错误输出被消费但不展示或记录，以免日志混入源文本或认证信息。

## 已执行的验证

2026-11-04，在 Windows 本机附带的 `codex-cli 0.164.0-alpha.11.1` 上验证，认证类型为 ChatGPT，实际模型为 Codex 返回的 `gpt-6.1-sol`：

| 验证 | 结果 |
|---|---|
| 真实原句 `We sat on the bank of the river.` 的解释 | 返回“河岸”、正确中文译文及基于 `of the river` 的解释，schema 校验通过 |
| 默认配置的首轮耗时 | 22.9 秒，包含连接准备和模型生成 |
| 使用应用默认 low effort 的首轮耗时 | 17.6 秒，包含连接准备和模型生成 |
| 同一进程、同一捕获的真实追问 | 6.0 秒返回完整回答，首次文本 delta 约 6.0 秒 |
| Ubuntu 24.04 WSL 真实解释 | Linux 版 0.164.0-alpha.11.1 使用该 Linux 用户已有的 ChatGPT 登录，30.2 秒返回通过校验的解释 |
| Ubuntu 24.04 WSL 同一捕获的真实追问 | 首次文本 delta 约 1.9 秒，完整回复约 3.3 秒 |
| Linux 旧版检测 | `/snap/bin/codex` 的 0.114.0 缺少 `environments` 协议字段，被明确拒绝；未修改或升级它 |
| 协议隔离测试 | 已覆盖常驻连接、结构化输出、流式追问、格式错误、失败状态、取消后重试、拒绝操作请求、有限等待时间 |

以上是少量实测样本，不是 p50/p95 或响应时间承诺。Linux 验证在 WSL Ubuntu 24.04 中完成，使用已有 VS Code 扩展包内的 Linux 可执行文件，不代表所有发行版或打包形式已验证。后续 Windows 与 Linux 打包桌面程序也完成了真实解释、提前收藏和重启恢复验证，详见 [桌面验证记录](verification.md)，其中区分了已覆盖的窗口与采集流程以及仍需手动确认的环节。运行协议测试：`npx tsx --test tests/provider.test.ts`。
